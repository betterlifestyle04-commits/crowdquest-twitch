# CrowdQuest — Security fixes and release validation (October 29, 2026)

## Dependency remediation

A GitHub Actions npm audit on the previous lockfile found four advisories:

| Dependency | Original severity | Remediation |
|---|---|---|
| vitest | Critical | Upgrade to `5.0.5` |
| tinypool (transitive) | Critical | Updated through Vitest 5 |
| @vitest/mocker (transitive) | Moderate | Updated through Vitest 5 |
| zod | High | Upgrade to `4.6.7` |

The exact new dependency manifest and lockfile were generated by npm during an isolated CI rehearsal. The upgraded setup passed tests, TypeScript and production build and yielded zero vulnerabilities in `npm audit`. Those reproducible, validated changes were then committed to the development branch.

**Do not run `npm audit fix --force` manually.** The lockfile now contains the tested upgrades.

In GitHub Actions, `npm audit --audit-level=moderate` is now a blocking check. The human-readable report script is `scripts/audit-summary.mjs`.

These findings describe dependency advisories at the time of the run, not a guarantee that the entire application has no vulnerabilities.

## End-to-end HTTP smoke test

Run `npm run smoke` (after `npm ci`). The script launches isolated copies of the frontend and backend on ports **5177** and **3107**, using an ephemeral dummy streamer token and **no Twitch credentials**. It then verifies:

- Health endpoint and unauthorized host-control rejection (401)
- Starting a quest and joining/choosing a role through demo chat
- Route vote, encounter action, actual damage calculation and final result
- Reset to a clean lobby
- Rehearsal scene authorization/validation and explicit simulated participant identities
- Smart Host toggle and malformed setting rejection
- HTTP 200 responses for dashboard, spectator and overlay

The script always attempts to stop its child processes. The test is automated in the CI pipeline.

**Limitation:** It cannot verify real Twitch OAuth/EventSub delivery, actual visuals, Web Audio output, or OBS compositing. These still require a manual browser/stream test.

## Streamer launch checklist

The dashboard now includes a non-invasive **Stream launch checklist**:

1. Twitch socket connected (does not independently prove commands are arriving)
2. Streamer token entered if host-control protection is configured (not a verification of token validity)
3. Showcase rehearsal disabled (real chat not blocked)
4. A real `!join` observed and accepted in the recent command activity feed

The status is intentionally conservative and resets with the in-memory game session. It must never represent simulated demo events as real Twitch participation.

## Manual verification before release

1. Reconnect Twitch with a fresh rotated Client Secret (never paste secrets into the chat or commit them).
2. Confirm a real `!join` is recorded in Recent game commands with source TWITCH and is accepted.
3. Complete a full adventure with real Twitch chat: role, route and combat, through a resolved boss.
4. Open `http://localhost:5173/spectator` and test cinematic scenes visually.
5. Check `http://localhost:5173/overlay` in OBS at 1920×1080, including safe margins and visibility alongside stream graphics.
6. Test pause, resume, Smart Host ON/OFF, reset confirmation, and that Showcase Studio remains clearly simulated.
7. Verify that the sound button remains opt-in and the OBS overlay silent.
8. Record the genuine Twitch participation in the final hackathon demonstration.
9. Review Devpost submission information and current organizer rules before November 2, 2026.
10. Merge the draft PR only after manual verification of this development branch.
